# UX and product design

The work of researching how people use a product and designing its structure, behavior, look, and words so they can reach their goals. UX researchers, product designers, UI designers, content designers, and accessibility specialists use these terms with product and engineering teams.

## Terms

### User research

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| Generative research | Research to find needs and new opportunities | You explore a problem before any design exists | core |
| Evaluative research | Research that tests a design against its goals | You check a concept or design before release | core |
| Attitudinal vs. behavioral research | What people say versus what people do | You choose a method that fits the question | expert |
| Contextual inquiry | Watch and question users in their real setting | You need to learn real workflows and workarounds | core |
| Semi-structured interview | Interview with a set guide but room to probe | You run qualitative user interviews | core |
| Diary study | Participants log their experience over days or weeks | You study long or repeated behavior | expert |
| Research plan | Goals, questions, method, participants, and schedule for a study | You get a study approved and staffed | core |
| Screener | Questions that filter in the right participants | You recruit for a study | core |
| Discussion guide | Script of tasks and questions for a session | You prepare interviews or tests | core |
| Persona | Research-based profile of a key user group | You keep design choices tied to real users | core |
| Proto-persona | Persona built from team assumptions, not research | You start fast and flag what needs validation | expert |
| Empathy map | Grid of what a user says, thinks, does, and feels | You align a team on one user's view | core |
| Customer journey map | One user's steps, thoughts, and feelings toward a goal | You find pain points across touchpoints | core |
| Service blueprint | Journey map plus the staff and systems behind each step | You fix problems that start backstage | expert |
| Affinity diagram | Notes grouped into themes from research data | You synthesize interviews or test notes | core |
| Research synthesis | Turning raw data into findings and insights | You report what a study learned | core |
| Mental model | What a user believes about how a system works | You match structure and labels to user expectations | core |
| Double Diamond | Process of discover, define, develop, deliver | You plan the stages of a design project | core |

### Information architecture

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| IA (information architecture) | Structure, grouping, and labels of content and features | You organize a site or app before visual design | core |
| Sitemap | Diagram of screens or pages and their hierarchy | You document or plan the IA | core |
| User flow | Steps and decisions a user takes to finish a task | You design a task from entry to completion | core |
| Card sorting (open, closed) | Users group topics into categories they choose or you set | You learn how users expect content to be grouped | core |
| Tree testing | Users find items in a text-only menu structure | You test a hierarchy before visual design | core |
| Taxonomy | Controlled set of categories and terms | You build filters, tags, or large content sets | expert |
| Content inventory | Full list of existing content | You start a redesign or migration | expert |
| Content audit | Review of content quality against goals | You decide what to keep, fix, merge, or delete | expert |
| Navigation (global, local, breadcrumbs) | Visible UI for moving through the structure | You design menus and wayfinding | core |
| Information scent | Cues that tell users a link leads to their goal | You fix labels where users get lost | expert |

### Interaction design

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| Affordance | What an object lets a user do | You judge whether a control invites the right action | core |
| Signifier | Visible cue that shows where and how to act | You make an action discoverable | expert |
| Feedback | Response that shows the result of a user's action | You confirm actions or show system status | core |
| Progressive disclosure | Show core options first and advanced ones on request | You reduce clutter in complex screens | core |
| Cognitive load | Mental effort a design asks of the user | You simplify forms, choices, or dense screens | core |
| Fitts's law | Time to hit a target depends on its size and distance | You size and place buttons and touch targets | expert |
| Hick's law | Choice time grows with the number of options | You limit options in menus or decisions | expert |
| Jakob's law | Users expect your product to work like ones they know | You decide whether to follow a common pattern | expert |
| Happy path | Main flow with no errors or exceptions | You design the default task first | core |
| Empty state | What a screen shows when it has no data yet | You design first use or zero results | core |
| Error state | How a screen shows that something failed | You design recovery from errors | core |
| Skeleton screen | Placeholder layout shown while content loads | You design loading states | expert |
| Modal dialog | Overlay that blocks the page until the user responds | You need a decision before the user goes on | core |
| Onboarding | First-use flow that gets users to value | You design signup and first-run experience | core |
| Deceptive pattern (dark pattern) | UI that tricks users against their interest | You review flows for ethics and legal risk | core |

### Visual and UI design

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| Visual hierarchy | Order of importance shown by size, color, and placement | You guide the eye to the main action | core |
| Layout grid (columns, gutters, margins) | Column structure that aligns content | You lay out screens consistently | core |
| Spacing scale (8-point grid) | Spacing set in multiples of a base unit | You keep spacing consistent across screens | core |
| Type scale | Fixed set of font sizes, often built from a ratio | You define typography styles | core |
| Gestalt principles | Rules for how people see items as groups | You group related elements by proximity or similarity | expert |
| Responsive design | Layout that adapts to screen size | You design for web across devices | core |
| Breakpoint | Screen width where the layout changes | You spec responsive behavior | core |
| Mobile-first | Design for small screens first, then scale up | You set priorities for content and layout | core |
| Interaction states | Looks for default, hover, focus, pressed, disabled | You spec every state of a control | core |

### Design systems

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| Design system | Shared components, standards, and docs for building product | You scale consistent design across teams | core |
| Component library | Reusable UI elements with states, usage notes, and code | You build screens from standard parts | core |
| Pattern library | Reusable combinations of components for common tasks | You standardize flows like forms or sign-in | expert |
| Design tokens | Named values for color, type, spacing, and motion | You keep design and code values in sync | core |
| Semantic tokens (alias tokens) | Tokens named for their purpose that point to raw values | You support themes and dark mode | expert |
| Variants | Set versions of one component, like size or state | You build flexible components | core |
| Atomic design | Building UI from atoms to molecules, organisms, templates, pages | You structure a component library | expert |
| Governance (contribution model) | Process to propose, review, and release system changes | You manage who can change the system and how | expert |

### Usability and accessibility

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| Usability (ISO 9241-11) | Effectiveness, efficiency, and satisfaction for set users and goals | You define what "easy to use" means and how to measure it | core |
| Context of use | Users, goals, tasks, resources, and environment together | You scope a usability study or requirement | expert |
| Usability testing (moderated, unmoderated) | Watch users try real tasks to find problems | You evaluate a design or live product | core |
| Think-aloud protocol | Users say their thoughts while doing tasks | You run qualitative usability tests | core |
| Heuristic evaluation | Experts check a UI against usability principles | You need a fast review without users | core |
| Nielsen's 10 usability heuristics | Standard set of ten usability principles | You structure a heuristic review | core |
| Cognitive walkthrough | Expert steps through a task as a first-time user | You test how learnable a flow is | expert |
| Severity rating | Score of how much a problem hurts users | You rank usability findings | expert |
| Task success rate | Share of tasks users complete correctly | You report usability results | core |
| Time on task | How long users take to finish a task | You measure efficiency | core |
| SUS (System Usability Scale) | Ten-item survey that gives a 0 to 100 score | You benchmark perceived usability | core |
| SEQ (Single Ease Question) | One 7-point rating of task difficulty after each task | You compare how hard tasks feel | expert |
| WCAG (Web Content Accessibility Guidelines) | W3C standard for accessible web content | You set accessibility requirements | core |
| WCAG conformance level (A, AA, AAA) | Three tiers of success criteria to meet | You state the target, usually WCAG 2.2 AA | core |
| POUR (perceivable, operable, understandable, robust) | The four principles behind WCAG | You structure an accessibility review | expert |
| Contrast ratio | Luminance ratio between text and its background | You check text color (AA needs 4.5:1 for body text) | core |
| Target size | Minimum size of a tap or click area | You size controls (WCAG 2.2 AA: 24 by 24 CSS pixels) | expert |
| Keyboard accessibility | Every function works by keyboard, with visible focus | You spec focus order, focus indicators, and shortcuts | core |
| Screen reader | Software that reads the interface aloud | You test with assistive technology | core |
| Alt text | Text alternative that describes an image | You add images or icons with meaning | core |
| WAI-ARIA (Accessible Rich Internet Applications) | Attributes that expose roles and states to assistive tech | You build custom widgets that native HTML lacks | expert |
| Accessible name | Label that assistive technology announces for an element | You label icons, buttons, and form fields | expert |
| Inclusive design | Design that works for the full range of people | You plan for disability, age, language, and context | core |

### Prototyping and handoff

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| Wireframe | Low-detail layout of structure and content | You agree on structure before visuals | core |
| Mockup | Static, detailed visual of a screen | You review visual design | core |
| Prototype | Interactive model used to test a design | You test flows with users or stakeholders | core |
| Fidelity (low, mid, high) | How detailed and realistic a design artifact is | You pick the cheapest artifact that answers the question | core |
| Design critique | Structured feedback session on work in progress | You improve a design with peers | core |
| Design handoff | Passing specs, assets, and behavior to engineering | You move a design into build | core |
| Annotations | Notes on behavior, states, and edge cases in a design file | You make intent clear to engineers | core |
| Design QA (quality assurance) | Designer checks the built UI against the design | You review before release | core |

### Content design and UX writing

| Term | Plain meaning | Use it when | Tier |
|---|---|---|---|
| Content design | Shaping content from user needs into the right format and place | You plan what content a task needs | core |
| UX (user experience) writing | Writing the words inside a product interface | You write labels, buttons, and messages | core |
| Microcopy | Short UI text such as labels, hints, and errors | You polish small text that guides action | core |
| Voice and tone | Fixed brand personality versus feel that shifts with context | You write a content style guide | core |
| Plain language | Words readers understand on first read | You write for a broad audience | core |
| Error message | Text that says what went wrong and how to fix it | You write form validation or failure states | core |
| CTA (call to action) | The main action you ask the user to take | You label primary buttons and links | core |
| Content style guide | Rules for terms, grammar, and voice | You keep product text consistent | core |
| Content-first design | Writing real content before the layout | You avoid layouts that break with real text | expert |

## Phrasebook

| Generic words | Trade words |
|---|---|
| talk to users to learn what they need | generative research (user interviews or contextual inquiry) |
| see if users can use it | usability testing (moderated or unmoderated) |
| quick expert check of the design | heuristic evaluation (expert review) |
| our typical user | research-based persona (proto-persona if from assumptions) |
| map out what the customer goes through | customer journey map; service blueprint if backstage matters |
| organize the menu | information architecture (IA) and navigation design |
| list of all the pages | sitemap |
| the steps to do something | user flow |
| rough sketch of the screen | low-fidelity wireframe |
| clickable demo | interactive prototype (state the fidelity) |
| make it easy to use | improve usability |
| don't overwhelm people | reduce cognitive load |
| make the important stuff stand out | strengthen visual hierarchy |
| make it look consistent | visual consistency (design system or style guide) |
| reusable colors and sizes | design tokens (semantic tokens for themes) |
| works on phones too | responsive layout with defined breakpoints |
| make it accessible | WCAG conformance at a stated level (often 2.2 AA) |
| text is hard to read | investigate whether text fails WCAG contrast ratio (4.5:1 for body text), size, or legibility |
| buttons too small to tap | check target size against WCAG 2.2 (24 by 24 CSS pixels minimum) |
| works for blind users | screen reader accessibility |
| what shows when there is nothing | empty state |
| what shows while it loads | skeleton screen or loading state |
| the words on the buttons | microcopy and CTA labels |
| how we sound | voice and tone guidelines |
| give the design to the developers | design handoff with annotations and specs |
| check the built version matches | design QA |
| tricky design that pushes people | deceptive pattern (dark pattern) |

## Deliverable shapes

| Deliverable | Standard parts |
|---|---|
| Research plan | background, research goals and questions, method, participant criteria and screener, sample size, schedule, discussion guide, deliverables, stakeholders |
| Research report (synthesis) | goals, method and participants, key findings with evidence and quotes, severity or priority, insights, recommendations, next steps |
| Usability test report | tasks, participants, task success rate, time on task, SEQ or SUS scores, findings ranked by severity, video clips or quotes, recommendations |
| Heuristic evaluation | scope and screens, heuristics used, issue list with heuristic violated, location, severity rating, recommended fix |
| Persona | name and role, goals, needs and pains, behaviors, context of use, key quote, research basis |
| Customer journey map | actor, scenario and expectations, journey phases, actions, thoughts, emotions curve, pain points, opportunities with owners |
| IA package | sitemap, navigation model, labels and taxonomy, card sort and tree test results, user flows |
| Wireframes and prototype | key screens, user flows, fidelity level, states (empty, loading, error, success), annotations, test tasks |
| Design spec (handoff) | final screens, all interaction states, responsive breakpoints, spacing and tokens used, components used, edge cases, accessibility notes (focus order, accessible names, contrast), copy |
| Design system component doc | name, purpose and when to use, anatomy, variants, states, behavior, tokens, accessibility requirements, do and don't examples, code reference |
| Accessibility audit | standard and level (for example WCAG 2.2 AA), scope, test method and tools, issues by success criterion, severity, steps to reproduce, fixes |
| Content style guide | voice and tone, word list and terminology, grammar and mechanics, UI text patterns (buttons, errors, empty states), accessibility and inclusive language |

## Misused or dated terms

| Term | Problem | Use instead |
|---|---|---|
| UX (used to mean UI) | UX covers research, structure, and behavior, not only visuals | UI design for the visual layer; UX for the whole experience |
| User testing | Suggests you test the user, not the design | Usability testing |
| Intuitive | Vague claim with no measure | Learnable, measured by task success or a cognitive walkthrough |
| ADA (Americans with Disabilities Act) compliant (as a design target) (US) | Only the 2024 Title II rule names a standard (WCAG 2.1 AA, state and local government); it is no target for others | WCAG 2.1 AA for Title II entities; WCAG 2.2 AA otherwise |
| Lorem ipsum in final designs | Hides content problems until build | Real or realistic content (content-first design) |
| Persona (made from guesses) | Looks like research but is not | Proto-persona, labeled as assumptions |
| Pixel perfect | Implies fixed layouts in a responsive world | Matches spec within tokens and breakpoints (design QA) |
| WCAG 2.0 or 2.1 as the latest | WCAG 2.2 (2023) is the current W3C recommendation | WCAG 2.2 |
